# 需求卡、岛屿地图、鱼、栖居地：调研与方案（2026-11-16 上午）

先例的完整表格已经汇总到 `docs/precedents.md`，这里只记本轮的需求、做法和结果。

## 主人的反馈

1. 兽的需求卡：显示数值或阈值，参照《模拟人生》；头脑风暴还有什么可以搬进来。
2. 兽的栖居地：不够程序化，表面太僵硬；找参考（洞、窝、房子、原生的东西），并想办法展示它的生成过程。
3. 地图："Streamling 1 / 2" 按钮看不懂（那是鱼）；标记应该在地图上、能点；地图形状看不出是我们的岛和山；去掉底下那行说明；参考游戏地图怎样引导玩家。
4. 鱼：形状怪；"Energy"看不懂；UI 和兽的不一样（字太多）；图鉴左栏没有体现程序生成。鱼应该有兽有的东西。
5. 所有先例都记下来，之后放进 Ideas 页。

## 本轮做法（按顺序）

1. **需求卡**（`LifeCard.tsx`，共用）：头像、标题、在做什么、需求条（数值、阈值竖线、按离阈值距离变色、趋势箭头）、心情词。兽和鱼用同一张卡；鱼只有一个需求"体力"，有两条线（低于它逆流歇息，高于它出去巡游）。
2. **地图**（`IslandNavigator.tsx`）：用高度场画晕渲和高度色，水来自水面数据，加岛的边缘；兽和每条鱼是地图上可点的标记，悬停显示名字；去掉按钮和说明文字。
3. **鱼的形态**（`FishSchool.tsx`、`streamFish.ts`）：鲤鱼/锦鲤的比例（钝头、最高点在三分之一处、窄尾柄、叉尾、胸鳍腹鳍），真实长度 0.45–0.75 m，种子决定的玉斑代替浮在表面的鳞片椭圆。
4. **图鉴**：鱼的条目和兽的一样：同一张需求卡；左栏是同种子家族（六条鱼的剪影，标出这一条），代替大段文字；几个数字。

## 结果

1. **需求卡**（`LifeCard.tsx`、`CreatureStatusDock.tsx`）：
   - 每个需求是一条带数值（0–100）的条，条上的竖线就是模拟真正起作用的阈值：
     - 兽：饱腹 52、水分 50、体力 35，来自 `NEEDS.seek`；
     - 鱼：体力 28 歇息、68 巡游，来自 `FISH_RULES`。
   - 悬停竖线显示"低于此值它会……"。
   - 颜色四档：高于阈值 15 以上为好，高于阈值为一般，高于阈值一半为低，再往下为危急（`JADE_UI.need*`）。
   - ▲/▼ 箭头表示变化方向和快慢。
   - 心情词取最差的那一项（"饥饿""有些口渴""安然"），头像边框随之变色，类似 plumbob。
   - 文字全部在 `strings.ts`（`life.*`）。
   - 在世界里或地图上点鱼，会打开它的卡；"查看形态 ↗"进入图鉴。
2. **地图**：
   - 从高度场画出（左上方来光的晕渲，低处比山峰暖一点，每 25 m 一条等高线），加水面和岛的边缘。
   - 地图旋转到和总览镜头同一个方向，山在上方。
   - 标记：最高峰和潭（文字），兽和每条鱼（按钮，悬停显示名字；同一个潭里的标记会散开）。
   - 去掉了按钮条和说明。点击地面就会飞过去。
3. **鱼的形态**：
   - `fishProfile`：钝头，最高点在三分之一处，尾柄是最高处的四分之一。
   - 体长 45–75 cm，体高是体长的 24–30%。
   - 长背鳍、胸鳍、腹鳍、臀鳍、叉尾；2–5 块由种子决定的玉斑画在身体的顶点色里。
   - 体力改为按岛时间走，每秒 0.004 / 0.008；游动按真实时间走。原来在 10 倍速下，体力不到 2 秒循环一圈，游速最高 1.7 m/s。
4. **图鉴的鱼条目**（`ResourceAtlas.tsx`、`FishFamily.tsx`）：同一张需求卡（嵌在页内）、五个数字、一句规则；左栏是同种子家族。（主人反馈：家族展示不出程序生成，下一轮改成"生长过程"，见 `plan-2026-11-16-b.md`。）

检查：`tsc` 无错，`check-world 684` 规则全部成立，`vite build` 通过；需求卡、地图、鱼的卡、图鉴条目都在浏览器里看过。
